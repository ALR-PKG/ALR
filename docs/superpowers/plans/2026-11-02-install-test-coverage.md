# Install Test Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Закрыть тестами основные ветки `Builder.InstallPkgs` и простые ошибки CLI без изменения пользовательского поведения.

**Architecture:** Табличные unit-тесты используют реальный `Builder`, небольшие fake-реализации только внешних интерфейсов и временные каталоги. Неинтерактивный оркестратор проверяется без PTY; интерактивные отмены и выбор остаются на уровне E2E, чтобы не тестировать моки вместо поведения.

**Tech Stack:** Go testing, testify, существующие build-интерфейсы, capytest для E2E.

**Spec:** Приоритеты аудита из диалога: ошибки, отмены, порядок, кэш, опциональные зависимости, затем CLI.

## Global Constraints

- Не менять поведение установки ради тестов.
- Не использовать реальный системный менеджер пакетов или сеть в unit-тестах.
- Проверять наблюдаемые результаты и вызовы внешних границ, а не внутренние детали.
- Не создавать коммит без отдельной просьбы.

## Review Focus

- Ошибки внешних операций возвращаются с контекстом и останавливают последующие вызовы.
- Уже установленные зависимости не переустанавливаются.
- Целевой пакет устанавливается после зависимости.
- `--clean` передаётся в существующий путь проверки кэша.
- Общая опциональная зависимость устанавливается один раз.
