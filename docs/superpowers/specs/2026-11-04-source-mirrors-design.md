# Зеркала исходников `sources_mirrorN`

## Цель

Разрешить автору `alr.sh` указывать несколько зеркал для каждого элемента `sources`, не меняя существующий формат `sources` и `checksums`. ALR последовательно пробует зеркала и затем основной URL, проверяет один и тот же ожидаемый checksum и использует общий кэш для всех адресов одного источника.

## Синтаксис

```bash
sources=(
  "https://upstream.example/app-1.0.tar.gz"
  "local://fix-build.patch"
)
sources_mirror1=(
  "https://mirror-one.example/app-1.0.tar.gz"
  ""
)
sources_mirror2=(
  "https://mirror-two.example/app-1.0.tar.gz"
  ""
)
checksums=("sha256:..." "SKIP")
```

Порядок кандидатов: `sources_mirror1[i]`, `sources_mirror2[i]`, …, `sources[i]`. Пустой элемент означает отсутствие зеркала. Допускаются distro-overrides, например `sources_mirror1_altlinux`.

## Правила

- `N` начинается с 1, наборы нумеруются без пропусков.
- После разрешения overrides каждый массив зеркал имеет ту же длину, что `sources`.
- Некорректный URL и нарушение структуры рецепта обнаруживаются до сетевых запросов.
- Один источник имеет один checksum независимо от числа адресов.
- `~name`, `~archive`, `~rev`, `~depth` и `~recursive` наследуются зеркалом из основного URL, если не заданы явно. Явно отличающиеся `~name` и `~rev` запрещены.
- Ключом кэша является нормализованный основной URL. Зеркала не входят в ключ семантического кэша собранного пакета.
- Сетевые ошибки, HTTP 4xx/5xx, ошибки чтения, недоступность Git/revision и checksum mismatch приводят к следующему кандидату. Отмена контекста, локальные ошибки ФС, нехватка места и ошибки рецепта fallback не вызывают.
- При `SKIP` ALR предупреждает, что эквивалентность содержимого зеркал не проверяется.
- Финальная ошибка перечисляет все адреса и причины неудач.

## Архитектура

`alrsh.Package` получает `SourceMirrors []OverridableField[[]string]`. Динамический декодер распознаёт `sources_mirrorN` и исключает эти имена из prefix-overrides обычного `sources`. Сборка использует `[]Source` с полями `URL`, `Mirrors`, `Checksum`, чтобы объединение подпакетов и удаление дубликатов не разрывали связи между данными.

`pkg/dl` получает канонический `CacheID` и список fallback URL. Перебор находится рядом с управлением кэшем, чтобы корректно обрабатывать неполные загрузки и ошибки обновления Git. Результат успешной загрузки через любой адрес записывается под ключом основного URL.

`SourceMirrors` сохраняется в БД и JSON/RPC. Генератор resolved-представления и разрешения overrides поддерживает срез `OverridableField`. Старые рецепты и записи БД работают без миграции данных.

## Подходы

Рассматривались отдельный массив `source_mirrors`, разделитель нескольких URL внутри `sources` и глобальная подмена хостов в конфигурации. Выбраны именованные наборы `sources_mirrorN`: они поддерживают несколько зеркал, существующие overrides и не меняют синтаксис текущих рецептов. Глобальная конфигурация остаётся возможным независимым расширением вне этой задачи.

## Не входит

- Автоматическое обнаружение зеркал.
- Параллельные или торрент-загрузки нескольких кандидатов.
- Пользовательская глобальная подмена хостов.
- Изменение семантики `SKIP` или отключение проверки checksum.
