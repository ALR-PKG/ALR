# E2E-образы ALR

Каждый образ содержит:
- базовый образ `latest` (образы намеренно отслеживают свежие релизы
  дистрибутивов; имена вроде `ubuntu-24.04` — это просто идентификаторы
  матрицы тестов, не версии содержимого);
- минимальный набор для работы ALR: `sudo`, `git`, `bash` (+ пакетный
  менеджер дистрибутива из базового образа);
- пользователя `alr` с passwordless sudo (настроено при сборке; пользователь
  добавлен в группу `sudo` на Debian-системах и `wheel` на остальных — ALR
  проверяет членство в привилегированной группе);
- `/bin/alr-test-setup` — скрипт, который вызывают тесты: `alr-install`
  устанавливает смонтированный в `/tmp/alr-bin` бинарник в `/usr/local/bin`
  (монтировать в `/tmp/alr` нельзя — это рабочая директория сборок ALR),
  `passwordless-sudo-setup` проверяет sudo.

Внешние сборочные зависимости (build-essential, rpm-build и т.п.) не нужны:
ALR собирает пакеты сам, внешне вызываются только пакетный менеджер,
`git`, `sudo`, `rpm`/`dpkg-query` (есть в базовых образах).

## Сборка

```sh
./build.sh
```

## Сборка и пуш в реестры

```sh
PUSH=1 ./build.sh \
  git.alr-pkg.ru/alr/alr-e2e-test-image \
  cr.gitverse.ru/alr/alr-e2e-test-image
```

Итоговые имена: `<prefix>-<distro>:latest`.

## Какой образ используют тесты

`e2e-tests/common_test.go` берёт префикс из переменной окружения
`ALR_E2E_IMAGE_PREFIX` (по умолчанию `git.alr-pkg.ru/alr/alr-e2e-test-image`).

Перед прогоном e2e соберите свежий бинарник: `make prepare-for-e2e-test`.
